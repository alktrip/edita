**Edita 1.0.0 rc 2**, la segunda versión candidata a la 1.0. Edita es un editor de texto nativo para Linux inspirado en Notepad++ (Qt 6, Scintilla 5, GPL v3).

*The second release candidate of Edita 1.0, a native text editor for Linux inspired by Notepad++. English below.*

Esta versión trae funciones nuevas que no estaban en la rc 1, así que pasan por una versión candidata antes de la 1.0. Si no aparece nada grave, la 1.0.0 será esta misma versión con otro número.

## Descargar

Ahora hay versiones para PC (**x86_64**) y para ARM de 64 bits (**arm64**: Raspberry Pi 4 y 5, portátiles y servidores ARM). `uname -m` dice cuál es tu equipo.

| Sistema | Archivo | Instalar |
|---|---|---|
| Debian, Ubuntu, Linux Mint | `edita_1.0.0.rc.2_amd64.deb` o `_arm64.deb` | `sudo apt install ./edita_*.deb` |
| Fedora, openSUSE y compatibles (**nuevo**) | `edita-1.0.0.rc.2-1.x86_64.rpm` o `.aarch64.rpm` | `sudo dnf install ./edita-*.rpm` o `sudo zypper install ./edita-*.rpm` |
| Cualquier otra distribución | `Edita-1.0.0-rc.2-x86_64.AppImage` o `-aarch64.AppImage` | `chmod +x Edita-*.AppImage` y ábrelo |

En x86_64 funciona en Ubuntu 22.04 o más nuevo, Debian 12, Fedora 36 y posteriores. En arm64 hace falta Ubuntu 24.04, Debian 13, Raspberry Pi OS 13 (trixie), Fedora 40 o más nuevos. Si ya tenías una versión anterior, instala esta encima: tu configuración se conserva.

> **macOS:** la versión para macOS se retomará después de la 1.0 para Linux.

## Qué cambia desde la rc 1

**Historial local** (Archivo › Historial local). Cada vez que guardas un archivo, Edita conserva una copia de cómo quedó, y la primera vez también lo que había antes. El panel muestra las versiones del documento: puedes compararlas con lo actual, volver a una (se deshace con Ctrl+Z), abrirla aparte o borrarla. No deja archivos junto a los tuyos. Se configura en Preferencias › Copia de seguridad: guarda 50 versiones por archivo, de los últimos 30 días, de archivos de hasta 2 MB.

**Tareas del proyecto** (Ejecutar › Ejecutar una tarea, **Ctrl+Mayús+B**). Edita encuentra lo que se puede compilar, probar o ejecutar en el proyecto del documento: Makefile, CMake, package.json (npm, pnpm, yarn, bun), Cargo, Go, pytest, Meson y just. La salida aparece en un panel con los errores subrayados: doble clic en uno te lleva al archivo y la línea. Los errores también aparecen en el panel Problemas. **Ctrl+F5** repite la última tarea.

**Git desde el margen.** Haz clic en una marca de cambios del margen para descartar ese bloque o prepararlo para el commit (stage), sin tocar los demás. **Ver › Git** muestra los archivos preparados y sin preparar, y desde ahí escribes el mensaje y confirmas el commit (Ctrl+Intro).

**Paquetes .rpm y versión arm64**, como se explica arriba.

Lo nuevo de la rc 1 (F12 y Alt+F12, letras de los menús, avisos de versiones estables, la API de plugins de la 1.x) está en sus [notas](https://github.com/alktrip/edita/releases/tag/v1.0.0-rc.1).

## Probar y reportar

Nos interesa sobre todo cómo te van las tres funciones nuevas y los paquetes nuevos. Para reportar un problema: **Ayuda › Reportar un problema…**. La guía [PROBAR.md](https://github.com/alktrip/edita/blob/main/PROBAR.md) dice qué probar. Guarda copias de lo importante, como con cualquier versión de prueba.

En arm64 el catálogo de plugins todavía no trae plugins ya compilados: el administrador ofrece compilarlos en tu equipo (hacen falta cmake y un compilador de C++), y eso aún no se ha probado bien en ARM. Si lo intentas, cuéntanos cómo te fue.

There are now builds for PCs (**x86_64**) and for 64-bit ARM (**arm64**: Raspberry Pi 4 and 5, ARM laptops and servers). `uname -m` tells which one your computer is.

| System | File | Install |
|---|---|---|
| Debian, Ubuntu, Linux Mint | `edita_1.0.0.rc.2_amd64.deb` or `_arm64.deb` | `sudo apt install ./edita_*.deb` |
| Fedora, openSUSE and compatible (**new**) | `edita-1.0.0.rc.2-1.x86_64.rpm` or `.aarch64.rpm` | `sudo dnf install ./edita-*.rpm` or `sudo zypper install ./edita-*.rpm` |
| Any other distribution | `Edita-1.0.0-rc.2-x86_64.AppImage` or `-aarch64.AppImage` | `chmod +x Edita-*.AppImage` and open it |

On x86_64 it works on Ubuntu 22.04 or newer, Debian 12, Fedora 36 and later. On arm64 it needs Ubuntu 24.04, Debian 13, Raspberry Pi OS 13 (trixie), Fedora 40 or newer. If you had an earlier version, install this one over it: your settings are kept.

> **macOS:** the macOS version will resume after 1.0 for Linux.

## What changes since rc 1

**Local history** (File › Local History). Every time you save a file, Edita keeps a copy of how it was saved, and the first time also what was there before. The panel lists the versions of the document: you can compare them with the current text, go back to one (Ctrl+Z undoes it), open it separately or delete it. It leaves no files next to yours. It is set up in Preferences › Backup: 50 versions per file, from the last 30 days, of files up to 2 MB.

**Project tasks** (Run › Run Task, **Ctrl+Shift+B**). Edita finds what can be built, tested or run in the project of the document: Makefile, CMake, package.json (npm, pnpm, yarn, bun), Cargo, Go, pytest, Meson and just. The output appears in a panel with the errors underlined: double click one to go to the file and line. The errors also appear in the Problems panel. **Ctrl+F5** runs the last task again.

**Git from the margin.** Click a change mark in the margin to revert that block or stage it for the commit, without touching the others. **View › Git** shows the staged and unstaged files, and there you write the message and commit (Ctrl+Enter).

**.rpm packages and arm64 builds**, as described above.

What was new in rc 1 (F12 and Alt+F12, menu letters, stable version notices, the 1.x plugin API) is in its [notes](https://github.com/alktrip/edita/releases/tag/v1.0.0-rc.1).

## Testing and reporting

We would especially like to hear how the three new features and the new packages work for you. To report a problem: **Help › Report a Problem…**. The [testing guide](https://github.com/alktrip/edita/blob/main/PROBAR.md#testing-edita) says what to test. Keep copies of what matters, as with any test version.

On arm64 the plugin catalog has no prebuilt plugins yet: the Plugins Admin offers to build them on your computer (cmake and a C++ compiler are needed), and that has not been well tested on ARM yet. If you try it, tell us how it went.
