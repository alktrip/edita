**Edita 1.0.0 rc 5**, la quinta versión candidata a la 1.0. Corrige un fallo de la rc 4 (y de las anteriores) que podía dejar la ventana de Edita en negro. Si usas la rc 4, actualiza.

*The fifth release candidate of Edita 1.0. It fixes a bug that could leave the Edita window black. If you use rc 4, please update. English below.*

## Descargar

Hay versiones para PC (**x86_64**) y para ARM de 64 bits (**arm64**: Raspberry Pi 4 y 5, portátiles y servidores ARM). `uname -m` dice cuál es tu equipo.

| Sistema | Archivo | Instalar |
|---|---|---|
| Debian, Ubuntu, Linux Mint | `edita_1.0.0.rc.5_amd64.deb` o `_arm64.deb` | `sudo apt install ./edita_*.deb` |
| Fedora, openSUSE y compatibles | `edita-1.0.0.rc.5-1.x86_64.rpm` o `.aarch64.rpm` | `sudo dnf install ./edita-*.rpm` o `sudo zypper install ./edita-*.rpm` |
| Cualquier otra distribución | `Edita-1.0.0-rc.5-x86_64.AppImage` o `-aarch64.AppImage` | `chmod +x Edita-*.AppImage` y ábrelo |

En x86_64 funciona en Ubuntu 22.04 o más nuevo, Debian 12, Fedora 36 y posteriores. En arm64 hace falta Ubuntu 24.04, Debian 13, Raspberry Pi OS 13 (trixie), Fedora 40 o más nuevos. Si ya tenías una versión anterior, instala esta encima: tu configuración se conserva.

> **macOS:** la versión para macOS se retomará después de la 1.0 para Linux.

## Qué cambia desde la rc 4

**La ventana ya no se queda en negro.** Con un documento que tiene una línea muy larga que la ruta de navegación muestra como un tramo (por ejemplo, una etiqueta XML de miles de caracteres en una sola línea), la ruta pedía todo ese ancho a la ventana. En Wayland (KDE, GNOME), la ventana se estiraba hasta decenas de miles de píxeles y se veía negra; como Edita vuelve a abrir la sesión, pasaba cada vez que se abría. Ahora cada tramo de la ruta se recorta a 60 caracteres (el texto completo está en su descripción) y la ruta nunca ensancha la ventana.

Si te pasó con la rc 4: instala esta versión encima y Edita vuelve a abrirse normal, con tus documentos.

Todo lo nuevo de la rc 4 (CSV, JSON y YAML, panel TODO, historial de Git, filtro de carpetas, F1 contextual, Acerca de, plugins para arm64) está en sus [notas](https://github.com/alktrip/edita/releases/tag/v1.0.0-rc.4).

## Download

There are builds for PCs (**x86_64**) and for 64-bit ARM (**arm64**: Raspberry Pi 4 and 5, ARM laptops and servers). `uname -m` tells which one your computer is.

| System | File | Install |
|---|---|---|
| Debian, Ubuntu, Linux Mint | `edita_1.0.0.rc.5_amd64.deb` or `_arm64.deb` | `sudo apt install ./edita_*.deb` |
| Fedora, openSUSE and compatible | `edita-1.0.0.rc.5-1.x86_64.rpm` or `.aarch64.rpm` | `sudo dnf install ./edita-*.rpm` or `sudo zypper install ./edita-*.rpm` |
| Any other distribution | `Edita-1.0.0-rc.5-x86_64.AppImage` or `-aarch64.AppImage` | `chmod +x Edita-*.AppImage` and open it |

On x86_64 it works on Ubuntu 22.04 or newer, Debian 12, Fedora 36 and later. On arm64 it needs Ubuntu 24.04, Debian 13, Raspberry Pi OS 13 (trixie), Fedora 40 or newer. If you had an earlier version, install this one over it: your settings are kept.

> **macOS:** the macOS version will resume after 1.0 for Linux.

## What changes since rc 4

**The window no longer stays black.** With a document that has a very long line that the breadcrumbs show as a segment (for example, an XML tag thousands of characters long on a single line), the breadcrumbs asked the window for all that width. On Wayland (KDE, GNOME), the window stretched to tens of thousands of pixels and looked black; since Edita reopens the session, it happened every time Edita was opened. Now every breadcrumb segment is cut to 60 characters (the full text is in its tooltip) and the breadcrumbs never widen the window.

If this happened to you with rc 4: install this version over it and Edita opens normally again, with your documents.

Everything new in rc 4 (CSV, JSON and YAML, TODO panel, Git history, folder filter, contextual F1, About, arm64 plugins) is in its [notes](https://github.com/alktrip/edita/releases/tag/v1.0.0-rc.4).
